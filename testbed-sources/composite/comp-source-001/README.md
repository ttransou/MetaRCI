# comp-source-001

## Source

* Source type: synthetic PowerPoint presentation
* File: `comp-source-001.pptx`
* Profile target: `composite`
* Intake ID: `comp-source-001`

## Purpose

This source is a bounded synthetic Composite testbed constructed specifically to exercise heterogeneous whole/part structure within one coherent logical presentation.

The specimen is intended to test whether independently meaningful internal components can retain distinct structural treatment while remaining related to a single parent source.

## Included Components

The presentation contains:

* multiple ordered slides;
* ordinary slide text;
* speaker notes;
* an embedded PNG image;
* a native PowerPoint table;
* a native PowerPoint chart with embedded worksheet data;
* an embedded MP4 video.

These components were selected deliberately to create pressure across Document-like, Media-like, and Structured Data-like structures within one parent presentation.

## Source Handling

The PPTX should be preserved as the original synthetic test artifact.

Any extraction, unpacking, normalization, conversion, or derived inspection output should be documented separately rather than replacing or silently modifying the source file.

## Testbed Role

`comp-source-001` is the initial Composite baseline specimen.

Its purpose is to test:

* parent source identity;
* independently meaningful component identity;
* source-native ordering;
* containment;
* heterogeneous component structure;
* relationships among parent and components;
* parent-level versus component-level metadata scope;
* and the boundary between meaningful logical components and low-level package artifacts.

The specimen does not define the final Composite contract and does not imply that every internal PPTX resource requires independent MetaRCI representation.

## Known Limitations

* The presentation is synthetic rather than a naturally occurring operational source.
* Component selection was intentionally designed to expose structural variety.
* Findings should therefore be challenged against an independently sourced presentation format, such as ODP, before being treated as portable Composite requirements.
